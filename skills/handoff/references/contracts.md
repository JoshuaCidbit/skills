# Handoff Schemas, Contracts & Executor Rules

## 1. `SYSTEM.md` — Global Environment Snapshot (`~/.agents/handoff/SYSTEM.md`)

- First line: `updated: <date>`, followed by `## Fingerprint` (`uname -a` first line, `ID`/`BUILD_ID` from `/etc/os-release`, `nproc`).
- **Literal-only:** every fact is a `$ command` line plus verbatim output generated by `scripts/sistema.sh` (shipped with this skill). Never paraphrase, round, or dump `env`.
- Regenerate when missing, user reports system changes, `updated:` > 30 days, or fingerprint mismatch. Re-verify negative claims (`ls`) at briefing time (`as of <date>`).
- **Stack tag filtering:** sections carry `<!-- tags: python, gui -->` (`always`, `python`, `node`, `web`, `go`, `rust`, `gpu`, `ml`, `dataviz`, `scientific`, `gui`, `container`, `db`). Include only `always` + tags matching root markers (`pyproject.toml`/`*.py` → `python`; `package.json`/`*.ts` → `node, web`; `go.mod` → `go`; `Cargo.toml` → `rust`; `Dockerfile` → `container`; `numpy`/`scipy` → `scientific`; `matplotlib`/`pyqt`/`gtk` → `gui, dataviz`; `torch`/`sklearn` → `gpu, ml`).

## 2. `handoff.md` — Persistent Task State (`<root>/.agents/handoff/handoff.md`)

Walk up to `.git`, `AGENTS.md`, or `.agents/` (never auto-resolve to `$HOME`; working inside `~/.agents/skills/<skill>` uses that folder as explicit root). Read `handoff.md` first on every invocation; never silently overwrite or reuse an existing `## Task:` slug (`<slug>-2`, etc.).

```markdown
# Handoff

# Project environment
- root: <path>
- explicit_root: yes|no
- vcs: git (<branch>) | none
- interpreter: <path> (<version>)
- layout: <one line per dir that matters>
- stack: <tags>
- project facts: <test command, constraints, etc.>
- negative claims as of: <date>

## Task: <slug>
- intent: <one line>
- mode: full | quick
- escalation_reason: <trigger or "-">
- step: comprehension | evidence_loop | plan | plan_audit | implementation | code_audit | executing | completed
- created: <date>
- head: <git HEAD>

### Decisions & Rejected Approaches
- [DECIDED] <what and why>
- [REJECTED] <what failed and why — injected in Stage 5>

### Consolidated State (Answers & Evidence)
- <condensed current snapshot>

### Raw answers
- <verbatim web model output>

### Open questions
- <unresolved items>

### NEXT_FOR_LOCAL_AGENT
- plan_phase: <n> of <total>
- current_step: <n>
- [ ] STEP 1 — <goal> | done_when: <expect> | result: <raw output>
- on_stop: <last mismatch, raw stdout/stderr>
```

## 3. Step Format (Stage 2 PLAN)

Max 7 atomic steps per phase; read-only checks first:

```text
STEP <n>
- goal: <one sentence>
- precondition: <read-only command> -> <expected output or state>
- action: <exact command, or SEARCH/REPLACE block per Return Contract>
- expect: <exact output, exit code, or file state>
- on_mismatch: STOP. Paste raw stdout/stderr. Do not retry or improvise.
- rollback: <exact command to undo>
```

## 4. Return Contract (Stages 4 & 5)

Every file block opens with `=== <path> ===` and closes with `=== END ===` (no unified `@@` diffs, no prose between blocks):

```text
=== path/to/existing_file.ts ===
<<<<<<< SEARCH
exact lines to match
=======
replacement lines
>>>>>>> REPLACE
=== END ===

=== path/to/new_file.ts ===
<full file content>
=== END ===
```

Followed by `SUMMARY`, `COMMANDS`, `RISKS`, and `NEXT`.

## 5. Executor Rules (Stage 6 Local Agent)

0. **Pre-flight audit:** before running a received plan, verify baseline state and confirm assumed paths/APIs exist; report plan defects as a delta packet instead of executing.
1. Execute **one step at a time**; verify `precondition` first or STOP.
2. Compare output against `expect` and write raw redacted stdout/stderr into `result:`.
3. On match, check `[x]` and continue.
4. On mismatch, STOP immediately, fill `on_stop:`, and report to the user (no retries or improvisation).
5. Never touch files or commands outside the plan.
